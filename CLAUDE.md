# Project rules for Claude Code

Read docs/PRD.md before any task. One milestone at a time.

## Truthfulness rules (non-negotiable)
- Never claim something works, passes, or was measured unless you ran the command this session and can show the output.
- Never invent metrics, kappa values, p-values, latencies, or counts. Run the measurement and save raw output to docs/evidence/.
- Before claiming files or commits exist, run ls / git status / git log and show it.
- If something is unverified, write "unverified". Do not soften it.
- README and resume text may contain only numbers found in docs/evidence/.
- Statistical claims must state sample size, method, and CI. Never report "improved" without a test.

## Anti-vacuous-pass rules
- Every test must be able to fail. For new behaviour, show it failing against a deliberately broken input before showing it passing.
- Never write placeholder tests (assert True, empty bodies).
- Unimplemented code raises NotImplementedError. Unimplemented make targets exit non-zero.
- make gate exits non-zero on any error, missing input, or empty eval set. An empty result is a failure, never a pass.

## Scope rules
- Create only the files listed for the current milestone. No stubs for future milestones.
- Do not add a dependency until the milestone that uses it. Never type a version number from memory: versions come from a lockfile generated by the tool, with the command output shown.

## Evidence rules
- "CI green" may only be claimed with the commit hash and the run URL. Save local output first, then push, wait for CI, then commit the evidence separately.
- ADR status starts as "Proposed". Only Nikhil marks an ADR "Accepted".
- Any factual claim in an ADR (licence terms, model capabilities, hardware limits) needs the source page or command output cited in the ADR.

## Held-out set
- Held-out file is excluded from default runner config. Record its checksum at creation; any run that reads it must log that fact to docs/evidence/.

## Working rules
- Plan first: files to change and how you will verify.
- Small commits, one concern each.
- Tests with every behaviour change, including tests for the statistics code against known cases.
- Never commit .env, credentials, or model weights.
- If a choice has trade-offs, write an ADR and ask before proceeding.

## Definition of done for a milestone
1. PRD acceptance criteria met.
2. Verification output saved to docs/evidence/Mx.txt.
3. make lint and make test pass locally and in CI.
4. README section updated, limitations written down.
